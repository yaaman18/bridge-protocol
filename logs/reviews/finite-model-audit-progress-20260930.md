## 最大の空白: DC2 が監査に入っていない

監査が判定しているのは、**グラフの外向き辺を境界とする DC だけ**である（`Witnesses.jl` の
`boundary`）。9/23 に加わった DC2 は、登録済み解析計画が全 case で記録すると定めているにもかかわらず、
有限モデル監査を一度も通っていない。DC2 には Lean の参照模型 M1〜M5 があるが、いずれも手で組んだ
抽象モデルで、測定由来のカタログ・条件の分離・含意行列には入っていない。

本日見つけた誤り1（DC2 からグラフ境界の DC は導けない）は、DC2 が監査に入っていれば含意行列の
`dc2 → hBound` の欄に有限反例として現れたはずのものである。**仕組みの構造は正しいが、
対象範囲が理論の進展に追いついていない。**

## 推奨

RSB-003 では DC2 の Julia 実装がどのみち必要になる。そのとき同時に監査へ入れるのが効率がよい。

1. DC2 の Julia 判定を、ERIEC の演算子を使わない直接の量化式と全符号化で照合する（DC と同じ方式）。
2. カタログの述語に `dc2`・`hSelf2`・`hHingeNeeded`・`hUnit`・`beta_nonempty` を加える。
3. 含意行列で `dc2 → hSelf / hSMC / hAct` に有限反例が無いこと（`DC2.toDC` と整合）と、
   `dc2 → hBound`（グラフ境界）に有限反例があること（本日の誤り1）を機械的に確かめる。
4. DC2 自身の条件について、全条件と単独脱落の分離表を作る。
