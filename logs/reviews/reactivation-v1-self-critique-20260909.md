# 再活性化基体 v1 の自己批評

結論: 再現可能な有限観測の設計としては具体化できているが、自己維持を測る意味の設計が未成熟。
現在の候補をそのまま凍結して実装することは推奨しない。
対象は `specs/drafts/reactivation-substrate-v1-design.md` と candidate TOML。
ユーザーの自己批評依頼に対する読取・数式の監査であり、候補のsimulation/DC列挙、ゲートは実行していない。
以下の導出は定義からの手計算であり、Leanで証明したとは主張しない。

## 1. 立ち上がりの依存を現在の維持依存と混ぜている（最優先）

§5はt=0からt=6までclampし、§6はその末尾の持続喪失を測る。
ある出力が起動に一度だけ必要で、その後は内部の相互結合だけで維持できても、
初期からその出力を止めれば立ち上がらず、維持への依存としてπ/ρへ記録され得る。
「この状態に至るのに必要だった」と「この状態を今後保つのに必要」は別の命題。
候補には閾値1の内部相互結合があり、この区別は本設計の構造に関係する。
これは単なるhorizon不足でなく、介入開始時点が研究上の問いと対応していない問題。

修正方向: 固定時間の準備実行で得た同一snapshotから対照と介入を分岐させる維持protocolを定義する。
初期からのclampは成立過程のprotocolとして区別する。準備時間をDC結果で選ばない。
この修正も永久的維持を証明するものではなく、指定した将来期間の依存を測る。

## 2. 自己喪失除外は無害な補正ではない（最優先）

本案ではK=Persist(B)、D(a)=(K\Persist(J_a))\{a}、π(m)=D(m)、ρ(c)=D(c)∩O。
よって全mについてπ(m)⊆Kかつm∉π(m)、全cについてρ(c)⊆K∩O。

K≠∅でhSelfが成立すると仮定する。

- K∩O=∅ならρ⋆(K)=∅、Φ(K)=∅となりhSelfに反する。
- K∩O={m}ならΦ(K)はπ(m)の部分集合だがm∉π(m)。m∈Kを覆えずhSelfに反する。

従って **非空KでhSelfが成立するには |K∩O|≥2 が必要**。
今回O={u6,u7}なので両出力のpersistenceが必要で、u6を覆うのはπ(u7)、u7を覆うのはπ(u6)に限られる。
したがって互いへのoff介入によって他方の持続が失われる関係まで必須になる。
単一出力、互いに代替可能な出力、独立に維持される複数出力を、研究上の根拠を述べず排除している。
「自己強制offを数えない」という局所的な対策が、出力間の必須相互依存という大きな仮定を持ち込んだ。

修正方向: 自己効果の生の観測を残し、解釈上の診断と関係定義を分けて再設計する。
単純に除外を戻せば自己ループの自明な成立が再発するため、戻すだけでは解決しない。
介入が何を停止し何を維持するのかを先に決め、単一出力・冗長支援・起動だけの支援を識別する意味的fixtureを用意する。

## 3. 同じKで関係を測り、そのKを検査している

π(m)⊆Kなので、どのYについてもΦ(Y)⊆K。
したがってhSelfのK⊆Φ(K)が通ればΦ(K)=Kとなり、さらに任意の不動点YはKに含まれる。
つまりこの測定法では、通過時のKは測定されたΦの最大不動点でもある。
これはhSelfが常に真という意味ではない。Kを関係の値域に埋め込んだ結果、成功時の最大性まで形で決まるということ。
κと独立にνΦを発見し、両者の整合を確かめた証拠とは解釈できない。

さらにqごとに関係を作り直すため、同じ基体の全状態に対する一つの固定Φを扱っていない。
各qのERIEStateに型が付くことと、固定した系の時間的な自己維持を証明することを分ける必要がある。
異なる初期履歴が同じ末尾窓に合流する場合も、末尾窓だけからcase固有の関係が決まるとは未証明。

## 4. 活性の持続と自己維持の距離

C=ユニットという前提は守る。しかしユニットの同一性、配線、閾値、更新を続ける計算機構は外部から恒久供給される。
offは活動停止であって、ユニットの消失・補修・再生成ではない。
本案が直接測るのは活性の持続への依存であり、構成条件を系自身が作り直していることではない。
固定基体のtoyであること自体が誤りではなく、どこまでの自己維持を代理しているかが未記述なのが問題。
損傷・代謝を追加すれば自動的に解決するとも限らず、まず主張をこの観測範囲に限定する。

κの「4点連続on」は、交代で役割を果たす回路・周期活動・休止を挟む組織的持続を空として扱い得る。
これは選好スコアを入れないことと両立する観測上の選別。persistenceのみという前提から連続onは一意に導けない。
一方で常時onが最大化するKに対し、K=CならhBoundが必ず落ちる。
持続活性が多いほど自己維持証拠が強いという単純な説明はできない。

## 5. 環境・境界・行為の解釈

M→Eの経路は必要なデータとして含めたが、固定W_envによる再帰があるだけで環境との相互作用の豊かさは得られない。
EとMは設計者がラベル付けした端子集合で、行為は系が選んだ出来事でなく観測者が実施する強制介入。
Actの非空性は二関係の共通要素の存在であり、その行為を系自身が実際に実行したことの証拠ではない。

境界は「Kから外へ非零辺がある」と定義した。遮蔽・選択的透過・境界の自己修復は検査しない。
支持外へ影響しない完全な活動集合は落ち、使われていない弱い構造辺でも境界はできる。
この結果を身体境界の成立と言い換えない。out方向とW_env包含を選んだ理由も研究目的との対応で再検討する。

## 6. 関係の合成が物理的な過程の合成になるとは限らない

α、σ、π、ρは異なるclamp下で得られる。集合像を合成するLean/Julia計算は正しくても、
e→mとm→cが別々の反実仮想で成立したことから、同じ実行中にその鎖が作動するとは限らない。
単一lesionは冗長な支援を見逃し、on/off差分は十分性と必要性を同一にはしない。
手順を厳密に再現するcertificateは、この解釈上の飛躍を埋めない。

`docs/ERIE_C_requirements.md:17` はM2の随伴を要件に挙げる一方、
`formal/ERIEC/DC.lean:6-18` のDC構造にはhGCがない。
本案のhGCを要求しないadapterはDC単独の検査として整合するが、ERIE-C全体の適合性には届かない。
既存check_DCを無変更で通せることを、未充足のM1〜M4の代わりにしない。
旧要件文書のLenia固有部分は最新の基体変更指示に従い、本指摘では復活させない。

## 7. 実装上の優先問題

| 問題 | 影響・修正方向 |
|---|---|
| H=2kを強制 | κの窓を変えるとα/σの観測時刻まで変わり、抽出の感度と物理的な伝播時間が混ざる。準備時間・介入時間・κ窓を別パラメータとして意味を確定する。 |
| 最終点だけの差分 | 途中で作用して戻った経路を見逃す。時間全体の効果か最終時点の効果かを問いとして選び、後から通る方へ切り替えない。 |
| 単一実装で生成と再検証 | 同じ更新バグを再現してPASSし得る。小さい手計算fixtureと、単純な独立参照実装で更新・clamp・抽出を照合する。 |
| q単位の関係・可変集合 | 別caseの関係の混入や集合の後変更でcertificateの意味が壊れる。完全なcase/profile/窓束縛とコピー/不変データを要求する。 |
| プロトコル版文字列とcommit | 版名やRの記録だけで、未コミットコード・依存・実行環境がRと一致するとは限らない。管理runの実行snapshotと依存を固定する。 |
| 独自canonical形式 | 小さいTOML候補に専用serializerを増やし、数値型・文字集合・順序の別の実装契約を作っている。既存の実績ある方法との比較なく採択したのは過剰。 |
| 事前登録を先に肥大化 | 再現性は高めても測定の妥当性は高まらない。まず意味のfixtureを確定し、登録機構を必要な信頼境界に限定する。 |
| 全256件という見栄え | 全列挙できるのは一配線・一閾値・一時間幅の初期配置だけ。基体の設計空間や持続期間に対する網羅性はない。 |

## 8. 私の設計判断への批評と次の順序

私は「実装が明確」「型が合う」「全件報告できる」を先に満たし、
どの反例なら測定の意味が誤っていると言えるかを先に定めなかった。
8ユニット、出力2個、H=6、連続4点on、対象自身の除外は研究判断であり、
合理的な唯一解であるかのように一組へまとめるべきではなかった。
通過率で選ばないという宣言も、設計者が構造へ入れた選別を消してはくれない。

次に設計すべきなのは、(1)起動と維持の区別、(2)単一出力と冗長支援を排除するのか、
(3)単一窓の依存をどこまで自己維持の証拠とするか、の意味契約。
これに対応する最小の正負fixtureを作り、π/ρと介入時点を再設計してから、数値基体と登録手順を凍結する。
現在候補でDCが何件通るかを見て修正方針を選ばない。
保持すべき長所は、既存DCを改変しないこと、負の結果を保存すること、有限集合の厳密計算、
測定由来・産出・viability・現象性を同一視しないこと。

変更は本批評文のみ。設計候補・台帳・実装の変更、他agentへの連絡は行っていない。
