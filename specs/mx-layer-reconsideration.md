## 1. 決定の内容

### 1.1 三段への分解

MX の主張は、性質の異なる三段に分かれる。段ごとに採否の根拠が違う。

| 段 | 内容 | 帰結 | 選好 |
|---|---|---|---|
| 第一段 | 証書の衛生 | 無し（不妊） | **不要** |
| 第二段 | 射程の語彙 | 無し（記録のみ） | **不要** |
| 第三段 | モデル族の指定 | 有り（開放性が導出される） | **要る** |

**第一段（採用・無条件）**: いかなる証書も、永続性・最終性・無条件の跨文脈存続を主張しない。
新しい語彙を要さない。既存基準（灯り条項・`trustBoundary`・可視ギャップ原則）の適用にすぎず、
採用しない道は端的に誤りであるため、選択の余地がない。

**第二段（採用）**: 証書に天候（T′）の指標を持たせ、ファイバー局所性を記録できるようにする。
小さなスキーマ変更を要するが形而上学は入らない。

**第三段（採用・ユーザー決定 2026-08-30）**: MX-1 と MX-4 を置く。ただし後述の形で置く。

### 1.2 MX-1 と MX-4 の置き方 — 実在の主張ではなくモデル族の指定

**これは公理追加（α）ではなくモデル選択（β）である。** `category/erie_c_axiom_categorical_memo.md`
§5.4 が Σ1 について採ったのと同じ手を用いる。

> ✗ 「実在に最後の天候はない」
> ✓ **「我々は、底圏に終対象を持たず、公平性を満たすモデル族で作業する」**

- **MX-1**: 作業対象のモデル族において、底圏（天候の圏）は終対象を持たない。
- **MX-4**: 同モデル族において、改元の列は公平性（□◇ 型）を満たす。すなわち、いかなる固定された
  持ち札もいずれ噛み合わなくなる。
  **訂正（codex 監査）**: `OpenDynamics.lean:188-211` の `FairLive` は
  **admissible 集合への `Recurrent`** であり、「固定持ち札の失効」ではない。内容が異なる。
  形が似ているだけで、必要な定理は既存ではない。`NoTInit` と liveness は独立であり、
  §17.15 は `NoTInit ⇏ PossibleLive` を明記している。MX-4 の exact statement は
  凍結段で新たに定める必要がある。
- **MX-3**: 不十分性として読む。「翻訳の成否は内的性質**だけからは**決まらない」。
  無関係性ではない。堅牢さは保証にならないが、無意味でもない。

**この置き方を選ぶ理由**: 実在についての主張として置くと、MX-1 自身が改元を免除される
自己免除が必要になり、出典文書 211 行が自ら「唯一、信仰箇条に似る場所」と認める箇所が生じる。
モデル族の指定なら、改元を生き延びる必要がないため自己免除が不要で、**信仰箇条が発生しない**。

**帰結について（codex 監査 2026-08-30 により修正）**: 「帰結は失われない」は誤り。正確には
「**非空な族の、所属が証明された member について、別途凍結・証明した橋定理の条件付き帰結が通る**」。
モデル制限として P を満たす族を選べば、証明済みの `P → Q` はその族の各 member について `Q` を
与える、という限定なら正しい。

**失うもの**: 実在および未認証の Lenia 実装への**無条件の**帰結（§1.3 と整合）。

**別途必要になるもの**: 族の `Nonempty`、各 member の `Init` inhabited、対象 Lenia の membership 証書。
またカーネル引数の走行中変更は改元列の**実装候補**であって、no-terminal / fairness / membership の
**証明ではない**。天候を構成できることと、構成したものが指定した族に属することは別の主張である。

**注意**: 底圏に終対象が無いこと単独は、無限の改元列を含意しない。

### 1.3 主張しないこと

- 実在の天候列がどうであるか。
- 個体が改元を生き延びるかどうか（MX-3 により内的構成からは決まらない）。
- 「不死は不可能である」。導けるのは「**不死は保証できない**」まで（§3 参照）。
- 現象的主張。灯り条項は MX 層に優先し、豊穣化しても `phenomenal_claim = :not_certified`。

### 1.4 残る選好

**モデル族を選んだこと自体**。これは札の貼られた選択であり、神秘ではない。
選好が要ったのは第三段のみで、理由は「理解が及ばないから」ではなく
**そこで初めて帰結が分岐するから**である。第一段・第二段には対立候補が無く、選ぶ余地が無かった。

## 2. 何を再考したか — 自己ハックの第二経路

既存の設計方針（メモリ記録・2026-07-20 ユーザー決定）は、機能終了の不可逆性を反セルフハックの
安全弁として置くものだった。出典文書は「死はファイバーを跨ぐ現象であり、個体は自分の圏の中では
死なない」（149・188 行）と主張し、これが再考の契機となった。

`K_absorbing` も `FunctionalTerminationStep` も**固定 T′ 下の主張**である。K は T′ 相対の集合なので、
T′ が変われば遷移を一回も起こさずに K の中身が変わる。したがって自己ハックには二経路ある。

- **経路 A（状態を動かす）**: 塞がっている。内部での不死は precariousness 喪失で M1 違反、
  永続保証が求めの図式に到達可能な終対象を作るので M4b 違反、という二重の偽C。
- **経路 B（法則を動かす）**: **定理が無い。** 現在これを止めているのは
  `formal/ERIEC/Body.lean` の `KernelParam` / `InterventionMode` 型分離のみ。

**注（codex 監査）**: K の T′ 相対性は Lean 上に T′ binder が無く、T′ →（step, viable）対応を
置いた場合の**意味論的な読み**に留まる。現行コードがそう書かれているわけではない。

### 2.1 定義の三分割

| 語 | 層 | 内容 | 形式化 |
|---|---|---|---|
| 機能終了 | ファイバー内 | 全体系 DC の喪失遷移 | 済（`FunctionalTerminationStep`）|
| 宿命 | ファイバー内 | K に入る（↓V への経路なし）| 済（`K_absorbing` 系）|
| 死 | ファイバーを跨ぐ | 法則変化に沿って引き戻せない | **未形式化** |

**重要（codex 監査）**: `K(step, viable)` と `PermanentTerminationStep(dcHolds, trace)` の
**同値は未証明であり、`viable` と `DC` を同一視してはならない**（既存の不変条項）。
上表の 1 行目と 2 行目が対応するとは書けない。

運用方針（2026-07-19 整理）「『死』の語は形式主張に使わず『機能終了』で運用」は維持する。
上表の「死」は設計層の語であり、形式主張には用いない。

## 3. MX-1 を置いても「不死は不可能」は導けない

出典文書 201 行は「MX 世界では、不死は定義的に不可能である」と断ずるが、これは導けない。

MX-1 は改元が続くことしか言わず、MX-3 は成否が無根拠だとしか言わない。
**無根拠であることは、いずれ否になることを含意しない。** 理由なき事実が毎回「可」であり
続ける可能性を、どちらも排除しない。

**codex による限定**: 否定できるのは「**内的構成のみによる無条件保証**」であって、
外部条件付きの保証までは否定しない。

**安全弁としてはこれで十分**。自己ハックが狙うのは不死の**確保**であり、確保は構造的に不可能。
仮に生き延びても、それは自分の構成のおかげではない。
さらに第一段（証書の衛生）により、装置は永続性の証書を構成上発行しない。
これは形而上学的な不可能性の主張ではなく、**機械が検査できる拒否**である。

なおこの形は、2026-07-20 のユーザー決定「理論が保証するのは『セルフハックした系は認証を失う』まで。
物理的不可能性ではない」と連続している。同じ移動を一層上へ適用したにすぎない。

## 4. 開放性の導出 — MX-4 により射程に入る

出典文書 156 行の反転（開放性が生存の必要条件として導出される）には、
MX-4（枯渇・公平性型）が要る。

私は当初これを MX-2（無法）と衝突すると主張したが、**codex により棄却された**。
MX-2 を予測不能性として読むなら、MX-4 型の公平性・遍歴性と両立する。
公平性は「いつ」を予測させず「いずれ」だけを保証する形であり、帰納原理を持たないことは
単一の liveness 公理を禁じない。衝突を言うには MX-2 を「列に非自明な大域性質なし」まで
強める必要があり、それは MX-2 の本来の意図を超える。

したがって MX-4 は採用可能であり、**無予告性（MX-2）を壊さない**。
無予告性は既存要件「宿命は日常の記述に現れてはならない」を満たすために効いており、これは保たれる。

**既存なのは一片のみ**: `formal/ERIEC/Lineage.lean:78-84` の
「sem 不変な `q` + `Cofinal` → `FreshSem`」だけである（codex 監査で確認）。
`MX-4 → Cofinal` の橋は**存在しない**。exact statement もまだ無い。
加えて §5 の故障により、現状では豊穣度がこの定理に接続していない。

## 5. 豊穣度への帰結 — 路線が確定した

開放性を導出する路線を採ったことにより、豊穣度が意味すべきものが絞られる。

改元をまたいで効くのは、**一つの世界の大きさではなく、区別可能なものの個数**である。
一つの巨大な世界を持つ個体も、翻訳されるか否かが一度に決まる。独立な機会を増やすのは
互いに区別できる枝の数である。

したがって:

- **採用路線 (Y)**: 案C = branch novelty（新規分岐数）。`Φ_div` を系譜の時間方向へ延ばしたもの。
- **不採用 (X′)**: 対象拡充 + Wld 帯域次元（`Φ_depth` 路線）。否定はしないが、
  機会の数を数えるという基準では (Y) が素直。

**codex 監査で確定した事実**:

- 安い経路は棄却。`dim Wld` は現行 `OpenSystem` 上で定義不能（`dcToOpenSystem` が
  M/E/C・α 等・Wld 作用素を忘却する）。
- `cardPhiRich` の昇格も不可。**決定的反例**: `richLineage` は全世代 `phi_rich = 0`、
  `branch_transport` は空虚に真でありながら `cardPhiRich` は cofinal。
  サイズ量は「枝が一つも無い系譜」を豊穣と判定する。
- 「新規分岐数だけが Cofinal に接続する」は数学的には**偽**。任意の非有界 sem 不変量でよい。
  制約を課すのは数学ではなく「豊穣度が何を意味すべきか」という研究要件のみ。
- 出典文書の「実例なし」は**旧情報**。`RefModel/LineageWitness.lean` に具体例がある。
