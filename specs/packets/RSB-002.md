## 1. 目的・解く問題

凍結した基体 v1 の上で、design-r2 §3〜§6 の観測（準備 trace、分岐 snapshot z、κ・ε、
全介入集合 A⊆C の発信停止、将来持続 Q_A、単項関係 π/ρ/α/σ、包含極小の喪失集合）を計算する
production の測定エンジンを作る。RSB-001 が義務として残した `start_run(token::VerifiedRegistration, ...)`
の実体をここで実装する。

**DC は評価しない。** 境界 boundary(K)、`ERIEState` の構成、`check_DC`、DC2 は RSB-003。

## 2. 確認済みの証拠（このセッションのツール出力に基づく）

- design-r2 §2〜§6 が測定の意味を式で定めている（F_A、J_A(0)=z、Q_A、D_A、π_z/ρ_z/α_z/σ_z、LossSets）。
- 独立 fixture `tools/experiments/reactivation_measurement_fixtures.jl` は 2026-09-27 に再実行して
  1391/1391 PASS。8 ユニットの候補を読まず、src/ERIEC にも依存しない。
- 凍結 profile `specs/reactivation-substrate-v1.toml` の `[output]` は `record_all_cases` と
  `phenomenal_claim` の2キーだけで、出力 schema の具体的な欄を持たない（RSB-001 IMPLEMENTATION-NOTES 項目2）。
- 計算量: 256 case × 256 介入集合 × H=6 更新 ≒ 39 万回の閾値更新（design-r2 §6）。単機で数秒の見込み（未計測）。
- 既存 `src/dc.jl` に `ERIEState` と `check_DC(sys, all_M, all_E, all_C)` がある（RSB-003 で使う）。

## 3. ユーザー判断（2026-09-27 決定済み、いずれも推奨案）

### R1. 凍結した基体での最初の run を、どの単位で行うか

- **推奨: RSB-002 では凍結 profile を走らせない。** 測定エンジンは合成 fixture と独立実装との照合だけで検証し、
  最初の実 run は RSB-003 で DC/DC2 adapter まで固定してから、測定から判定まで一度に行う。
  理由: 関係（π/ρ/α/σ）を先に見てから DC adapter を設計すると、解析計画の禁止する調整
  （結果を見てから解釈を変えない）の抜け道になりうる。
- 棄却した代案: RSB-002 で 256 case の測定だけを走らせて記録する。測定の確認は早いが、
  上の理由で RSB-003 の設計が結果を見た後になる。

### R2. 凍結 profile に出力 schema が無い問題の扱い

RSB-001 §3 は、出力 schema と必須生データを `profile_blob_sha256` の対象に置くと定めた。
凍結した v1 はその欄を持たないため、今のままでは出力の形式が profile digest に束縛されない。

- **推奨: 取り下げて出し直す。** RSB-002 で出力 schema を確定し、最初の run より前に
  `rsb-001-reactivation-substrate-v1` を `results_seen_before_withdrawal = false` で取り下げる。
  `[output]` を拡張した profile で新しい登録を行う（`supersedes` で旧登録を指す）。
  結果を見ていないので `preregistration_strength = full` のまま保てる。
  profile schema の validation version を `rsb-profile-schema-v2` に上げる。
- 棄却した代案: 出力の形式を runner commit（run 開始レコードに記録済み）にだけ束縛する。手間は少ないが、
  RSB-001 §3 の境界（何を出力するかは profile 側）から外れる。

### R3. 測定エンジンの置き場所

- **推奨: 新しい隔離パッケージ `tools/ReactivationMeasurement/`。** 依存は標準ライブラリと
  `tools/SubstrateRegistry` だけとし、ERIEC を読み込まない。RSB-003 の DC adapter は ERIEC 側に置き、
  測定エンジンが書いた記録ファイルを読むだけにする。測定と判定の分離が、依存関係として検査できる。
- 棄却した代案: `src/reactivation/` として ERIEC 本体に置く。RSB-003 との接続は簡単になるが、
  測定コードから DC を参照できてしまい、分離を構造で保証できない。

## 4. 仮説・未検証部分

- 出力 schema の欄（§5）は design-r2 §7 の記録項目から DC に関わるものを除いて作った案であり、RSB-003 の
  adapter が必要とする入力を過不足なく含むかは RSB-003 の設計まで確定しない。
- 実行時間の見積もりは未計測。
- 負の重みを schema は許すが、凍結 v1 の重みはすべて正（1）。負重みでの LossSets の非単調性は
  fixture でのみ検査される。

## 5. 出力 schema 案（R2 で profile `[output]` に固定する内容）

case ごとに一つの記録。集合はユニット index を LSB とする 8 bit マスク（0〜255）で表す。

| 欄 | 内容 |
|---|---|
| `case_id` | RSB-001 §7b の `case-NNN`（q = NNN） |
| `q` | 初期配置 |
| `preparation_trace` | x_0 … x_P（P+1 個のマスク） |
| `z` | 分岐 snapshot x_P |
| `kappa` | K = κ(s)（s は x_(P−k) … x_P） |
| `epsilon` | ε(s) = z ∩ I |
| `future_final` | 全 A（0〜255）の J_A(H) |
| `future_persistent` | 全 A の Q_A |
| `pi` `rho` `alpha` `sigma` | 単項関係（ユニットごとのマスク） |
| `loss_sets` | ターゲットごとの包含極小の喪失集合（マスクの列） |
| `collective_only_loss` | 単独停止では失わず、複数停止でのみ失うターゲットのマスク |

DC の4述語・Act・boundary・非空性は**含めない**（RSB-003 が記録から計算する）。

## 7. 意味変更の有無

- 理論の不変条項（層分離・M4・Σ-purity・`phenomenal_claim`）には触れない。対象層に対象・公理を足さない。
  介入の観測は対象層の新しい構成素として扱わない（design-r2 §10）。
- 既存 `src/`・`formal/`・`specs/ledger.toml` は変更しない。
- R2 の推奨を採ると、凍結済み登録の取り下げと再登録が起きる。これは登録記録への追記であり、
  中身・履歴は消さない。
