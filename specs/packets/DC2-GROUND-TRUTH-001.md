# DC2-GROUND-TRUTH-001: 埋め込んだ構造による hUnit（N3）の照合

- 作成: 2026-10-02（ユーザー指示「候補1の方針で実装して」）
- 対象: DC2 の hUnit = MutualPair（N3、`specs/packets/DC2-HUNIT-N3.md`）。比較用に旧 hUnit（`hUnit_v1`）も記録する。
- 正解の定義と型ごとのラベルは `tools/model_audit/fixtures/organization-ground-truth.toml` に置き、
  N3 を一度も適用しない段階でその SHA-256 を `logs/gates/DC2-GT-20261002/freeze.txt` に記録した。

## 1. 照合の形

同じ回路 x から2つの経路で「組織があるか」を出し、比べる。

- 上の経路: x を発信停止で測定し、関係モデル (π, ρ, κ) を得て、N3 を評価する。
- 下の経路 G: 生成器がその回路を**どの型として設計したか**から決まる正解。測定の読み出し（損失関係）を使わない。

## 2. 正解 G の定義（理論中立）

**G(x) = 真 ⟺ 設計上、x の持続する構成素の中に、2つ以上の異なるユニットからなるフィードバック閉路が埋め込まれており、
その閉路が閉路上のユニットの持続を担っている。**

- 「担っている」は設計の論証で決める（例: 閉路上の各ユニットは、閉路上の直前のユニット以外から持続に足る入力を受けない）。
- 運動ユニット（M）を経由するかどうかは **G の定義に含めない**。ERIE-C の産出は行為（M）を介するが、G は理論から独立な
  「現実側」の記述として置く。したがって運動ユニットを含まない閉路の型では、N3 と G が食い違いうる。
  食い違った場合、それが N3 の欠陥か、ERIE-C の「産出は行為を介する」という前提の帰結かは、ユーザーが判断する。
- 対の水準の正解: 各型は「埋め込んだ閉路」の一覧を持つ。N3 が挙げる相互産出の対 {c, d} は、c と d が**同じ**埋め込み閉路に
  属するときに限り正しい（対の健全性）。

## 3. 判定

| 指標 | 内容 |
|---|---|
| 型の一致 | 各型で N3（hUnit）と G が一致するか。偽陽性（N3 真・G 偽）と偽陰性（N3 偽・G 真）を区別して数える |
| 対の健全性 | N3 が挙げた対がすべて、同じ埋め込み閉路に属するか |
| 置換不変性 | ユニットの並び順を入れ替えた変種で結果が変わらないか |
| 設計の整合 | 測定した κ（持続集合）が、設計で予定した持続集合と一致するか。一致しない型は「設計の誤り」として照合から外し、報告する。この検査は軌道の持続だけを読み、π・ρ・N3 を読まない |

数値の閾値は置かない。偽陽性・偽陰性・対の誤りは、1件でもあれば撤回条件の該当としてユーザーへ報告する。

## 4. 独立性の限界（未検証の部分）

- 型とラベルを書いたのは、N3 の定義を知っている私（Claude）である。正解の付与は設計の論証によるが、どの型を選ぶかに
  N3 の知識が影響している可能性は排除できない。
- G は「意図した正解」であり、現実の生物・化学系との照合ではない（候補2・3は未着手）。
- 自己ループは回路形式で禁止されているので、「単独で自己維持するユニット」は作れない。組織を持たない型は、
  発振器に追随して持続するユニットで作る。

## 5. 反証条件

- 照合が自明に通ることが示されたら（どの型でも N3 と G が定義上一致してしまう）、この照合は情報を持たないので取り下げる。
- 設計の整合検査で多くの型が外れるなら、型の作り方を見直す（N3 の評価には進まない）。
